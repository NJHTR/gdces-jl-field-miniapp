# AI 执行过程：真实状态流转 + 多级可折叠 trace（设计评审）

## 结论

现在这不是「状态流」，是**执行结束后的命令日志**：跑的时候只剩一个 label 轮播，跑完一次性倒出全部命令。执行中是 `task.progress`、结束后是 `message.trace`，两套模型不接，所以「活动项自动展开」今天做不了——先改事件契约（`agent.py:1670` 只解析 `command_execution`，其余事件丢弃），再谈 WXML。

## 一、扁平 trace 的硬伤

1. 状态只有 running/done + ok 布尔，失败＝标题后加「（失败）」；无失败行、无错误码、无重试记录，引擎重试在 UI 上像「又跑了一遍」。
2. 无 stepId：progress 拿 label 当 `wx:key`（重名撞键），展开态按 index 存（`index.js:1181`），长列表和虚拟列表都做不了。
3. 层级塌缩：子智能体、读写文件、生成文书全塌成一行 22 字标签；note 是模型过程插话，混进状态流，既冒充状态又是 CoT 泄漏。
4. 两头都糟：展开 30~40 条平铺全是噪音，收起只剩「已完成 · 用时 X」。

## 二、阶段与状态

阶段 5 个：理解 → 计划 → 取材 → 动手（工具/写文件/子智能体/出文书）→ 收口（校验/完成）。

状态 6 个：排队、思考中、运行中、成功、失败、重试中。读写文件、子智能体、生成文书是 `step.kind` 标签，不是状态。失败必须带 `error.detail`，重试写「第 2 次」。

## 三、三层 IA

- **L1 轮次行**（默认收起）：摘要 + 结果 + 耗时，摘要用后端 `traceSum`，不让前端猜。
- **L2 步骤**：按阶段分组，默认只展开「进行中」那条，同时最多一条，点击切换。
- **L3 单步**：输入（工具 + 关键参数，脱敏）/ 输出（首 6 行 + 查看完整）/ 失败行高亮 + 重试。

折叠态按 `stepId` 存实例 Map，不进 data；滚出视口释放 L3。不做第 4 层。

## 四、CoT 隐私

不显示原文，只显示计划摘要（「先查规范、再比对历史，最后出通知单」）和结论摘要（「查到 JGJ 130 §6.4.3」）。模型插话要么结构化进 plan，要么丢弃；失败说「换了一种方式再试」。**靠契约保证**：后端只下发 summary，前端无原文可渲染。

## 五、Skyline 落地

- **折叠**：`wx:key="stepId"`；L3 用 `wx:if` 挂载，收起即卸载。
- **滚动**：整页滚动不动，trace 用 `scroll-view type="list"` 原生列表 + 固定行高占位。
- **性能**：单路径 `setData`（只改 `trace.steps[i].detail`），200ms 合并进度；L2 行高 88rpx、L3 自适应；output 不进 data，点开再取。
- **缩进**：每层 24rpx，竖线 2rpx 用绝对定位伪元素，不靠层层 padding。
- **状态色**：灰（排队/成功）、蓝（运行，仅圆点）、红（失败）、琥珀（重试）；成功不用绿，避免撞业务「已签」；色+形+文三通道。
- **动效**：160–220ms `cubic-bezier(.2,0,0,1)`，只动 opacity/transform/height；减少动画时即时。
- **可访问性**：`aria-role="button"`、`aria-expanded`，`aria-label` 带状态与耗时；触控 ≥88rpx；对比度 ≥4.5:1；输出 `selectable`。

## 六、竞品（只借三条）

Claude 一行一动作、结果可展开；Cursor 活动步骤自动聚焦、完成即收；Manus / Devin 把计划当一等公民、逐条打勾。**不学**虚拟机直播、终端全文、diff 视图——用户是工地监理，不是开发者。

## 七、MVP / 不做

**MVP**：step 契约（id / kind / state / summary / io 指针）+ 三态与失败详情 + L1/L2 折叠与活动项自动展开 + L3 输入输出 + CoT 摘要字段 + 单路径更新。

**不做**：无限层级树、子智能体嵌套 trace、实时终端、思维链原文、trace 搜索/导出、单步重试按钮（先只显示次数）、时间轴拖拽。
