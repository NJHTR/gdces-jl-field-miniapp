## 六、两个 JSON 字段的约定（可追溯的核心）

| 字段 | 结构 | 前端展示 |
|---|---|---|
| `messages.trace` | `[{ icon: string, text: string }]` | 助手气泡下方的折叠轨迹 |
| `messages.trace_sum` | `string` | 轨迹条（收起态） |
| `messages.ms` | `int` | 轨迹展开后的右下角 |
| `messages.quote` | `{ who, text, refId } 或 null` | 气泡内的灰底引用块 + 输入框上方的引用条 |
| `messages.sync` | `0 / 1` | 气泡下方元信息 |
| `docs.bases` | `[{ kind, ref, text, ic }]` | 文书详情页底部「依据」 |
| `bases 只存引用，不存原文` | `规范库更新后，文书里引用的条文跟着更新，不会出现「引的是废止版本」` | None |
| `trace 的文本由服务端生成` | `前端只负责渲染，换模型、换工具都不改前端` | None |
| `sync 必须落库` | `工地信号差，用户以为发出去了其实没传；重启后要能继续重发` | None |
| `quote 存 refId + 快照文本` | `被引用的消息即使被删，文书里仍能看到当时引的是什么` | None |

**四条原则**：

1. `bases` 只存引用不存原文 —— 规范库更新后，文书里引用的条文跟着更新
2. `trace` 的文本由服务端生成 —— 前端只渲染，换模型换工具不动前端
3. `sync` 必须落库 —— 工地信号差，重启后要能继续重发
4. `quote` 存 refId + 快照文本 —— 被引用的消息即使被删，文书里仍看得到当时引了什么
